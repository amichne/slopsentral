Software Engineering is the default plugin for code work.
It owns shared engineering rules and procedures for scoped delivery.
Language and platform specialties add their specific contracts.

## Skills

| Skill | Purpose |
| --- | --- |
| `semantic-ratchet` | Keep established facts in values and consumer contracts. |
| `tdd` | Define an independent executable result and prove the changed behavior. |
| `python-tooling` | Author locked uv automation with strict types, Ruff, and pytest. |
| `git-change-flow` | Protect local work and manage branches, diffs, and commits. |
| `pull-request-lifecycle` | Deliver an authorized branch or PR and examine its current checks. |
| `github-ci-operations` | Diagnose or change GitHub Actions and artifact delivery. |
| `issue-tracker-operations` | Read issues and direct blockers through the selected backend. |
| `mise-project-tooling` | Keep project tools and local environments explicit. |

## Shared rules

Parse external values once.
Pass refined values to consumers that need the established fact.
Keep pure decisions separate from external effects.
Represent expected failures as finite outcomes.

Use the smallest faithful executable evidence for the changed claim.
A missing tool or empty selection does not prove a product failure.
A plan does not authorize implementation.
Local implementation does not grant publication authority.

## Context hook

The `software-engineering-context` hook supplies the agent execution and engineering design instructions.
Its configured events cover startup, resume, clear, and compact.
The host owns trust, event delivery, and context consumption.
The instruction text does not prove model behavior.

The [plugin manifest](https://github.com/amichne/slopsentral/blob/main/source/plugins/software-engineering/plugin.json) owns composition.
The [engineering baseline](https://github.com/amichne/slopsentral/blob/main/source/instructions/engineering-design.md) owns the shared rules.
