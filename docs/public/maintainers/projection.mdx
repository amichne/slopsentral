The projector turns canonical source references into complete provider packages.
Pkl owns typed provider shapes. Node owns frozen reads, materialization, digest sealing, and process effects.
Authored source stays under `source/`. Generated trees and installed caches remain consumers.
The [projection concept](/knowledge/architecture/projection) explains the system relationships.

## Evaluate, seal, publish

1. Freeze regular source bytes and modes.
2. Examine the graph and resolve each plugin's dependency closure against those bytes.
3. Parse normalized input with `Decode.pkl` and `Schema.pkl`.
4. Evaluate `Project.pkl` for the provider manifests and copy plan.
5. Materialize payloads in memory and compute their digests.
6. Evaluate Pkl again with those digests to seal references.
7. Make sure that sealing preserves payloads and source evidence remains unchanged.
8. Write a complete sibling staging tree.
9. Publish the tree with an atomic operation that rejects an existing destination.

Missing assets, conflicting identities, cycles, incomplete plans, and changed inputs stop projection.
A failed publication removes only its owned staging directory.
Concurrent writers cannot replace a published tree.

The evaluator uses an isolated copy of versioned Pkl models.
Its allowlists permit the frozen input and explicit properties.
It cannot read ambient environment variables or remote modules.
The evaluator uses a 60-second limit and downloads no runtime.

The [native publication adapter](https://github.com/amichne/slopsentral/blob/main/tools/projection/publish_directory.py) uses `renamex_np` with `RENAME_EXCL` on macOS.
Linux uses `renameat2` with `RENAME_NOREPLACE`.
Unsupported systems or filesystems reject publication. No replacement fallback exists.

## Runtime and commands

Use a Git checkout with a resolvable HEAD.
The repository needs Node.js 22.22.0 or later, Python 3, and exactly Pkl 0.32.0.
The [runtime inventory](https://github.com/amichne/slopsentral/blob/main/tools/projection/pkl-runtime.json) pins supported platform archives and digests.
Its explicit installer rejects an existing destination.

```sh
npm ci --ignore-scripts
node tools/install-projection-pkl.mjs --out /tmp/slopsentral-pkl/pkl
export PKL_BIN=/tmp/slopsentral-pkl/pkl
node tools/project-marketplaces.mjs --source . --harness codex --out /tmp/codex-new
node tools/project-marketplaces.mjs --source . --harness github-copilot --out /tmp/copilot-new
node tools/project-marketplaces.mjs --source . --harness amp --out /tmp/amp-new
```

Use fresh output paths outside the checkout with existing parent directories.
The output contains the provider tree beneath that path.
Success emits `PROJECTED` on stdout.
Failure emits `PROJECTION_REJECTED` with a finite stage and code on stderr.
Pkl diagnostics name a known model location or `EVALUATION_FAILED`, without source payloads or raw process logs.

## Determinism and provenance

Inputs include frozen bytes and modes, HEAD commit time, versioned models, and the pinned evaluator.
Identical inputs produce identical payload bytes and modes.
Current time and temporary directory names do not enter output.

`marketplace-lock.json` records projected hashes and `generatedAt`.
Its `sourceSha` is a canonical source-tree hash, not a Git commit ID.
It includes sorted relative paths and source bytes separated by NUL bytes.
The projector excludes named output and cache directories plus `.pyc` files.
Source symlinks and non-regular files fail admission.
A digest proves byte agreement. It does not prove host discovery or instruction use.

## Compatibility and supported scope

Supported targets are `codex`, `github-copilot`, `amp`, and `pi`.
Only local marketplace assets are supported.
Remote resolution and provider overrides stop projection until their typed implementation exists.
A new shape needs accepted and rejected cases before distribution.

[Projection tests](https://github.com/amichne/slopsentral/blob/main/tools/tests/pkl-projection.test.mjs) exercise repeated output, copied bytes, modes, changed inputs, and competing writers.
[Provider fixtures](https://github.com/amichne/slopsentral/blob/main/tools/tests/projection-workflow-contract.test.mjs) preserve publication relationships.
These are generated-package results. Native host behavior needs separate evidence.
Historical projector comparisons remain in Git history rather than current qualification claims.

[Publish Harnesses](https://github.com/amichne/slopsentral/blob/main/.github/workflows/publish-harnesses.yml) updates Codex and Copilot trees together on `main` and their provider branches.
Amp publishes only to `harness/amp`.
[Stable releases](/reference/releases) keep immutable provider archives.
Local projection grants no publication authority.

## Amp native plugins

Amp output contains `.amp/plugins/<plugin>/index.js` plus complete skills, scripts, references, and instructions.
Use the [Slopsentral command](/guides/install) for managed system installation from a stable archive.
For manual project installation, copy complete selected bundles into `.amp/plugins/` without replacing existing directories.
Do not install only `index.js`.

A provider-branch checkout supplies another prebuilt source:

```sh
git clone --single-branch --branch harness/amp https://github.com/amichne/slopsentral.git /tmp/slopsentral-amp-published
git -C /tmp/slopsentral-amp-published rev-parse HEAD
git -C /tmp/slopsentral-amp-published log -1 --format=%B
```

Record its revision and `Source-Commit` trailer.
Choose one installation scope before a copy.

### Updates and rollback

For managed links, use the command's explicit update or removal operation.
The command rejects edited installed files and foreign destinations.

For manual copies, get the replacement in a fresh directory.
Stop affected Amp sessions before replacement.
Move old bundles outside every plugin discovery root.
Copy complete replacements into vacant destinations and keep unrelated plugins.
Reload Amp and inspect `amp plugins list` plus each selected bundle's qualified skill.
If discovery fails, stop the affected sessions before restoration.
Restore the saved bundle and reload Amp.

Manual replacement is not atomic and `amp plugins update` does not update copied directories.
Commands still need their declared tools and dependencies.

### Capability and evidence limits

[Amp mapping](https://github.com/amichne/slopsentral/blob/main/tools/projection/Amp.pkl) owns the declared `capabilities.json`:

| Capability | Amp behavior |
| --- | --- |
| Skills | Native registration with complete resources |
| Instructions | `agent.start` context on every turn |
| Hooks, agents, MCP | Reference material only |
| Workflow profiles | Unsupported |

Missing instruction files stop initialization before skill registration.
Shared skills can appear under two bundle-qualified names with the same source.
Package context grants no authority.

`npm run verify:marketplaces` exercises Codex, Copilot, and Amp adapters and installed scripts.
For optional native Amp discovery, select `AMP_BIN`:

```sh
AMP_BIN="$(command -v amp)" PKL_BIN=/path/to/pkl-0.32.0 node --test tools/tests/amp-projection.test.mjs
```

CI runs adapter tests. Native Amp discovery needs the selected executable.
Neither result measures model routing or instruction adherence.
Use the [Pi guide](/guides/pi) for its separate native adapter.
