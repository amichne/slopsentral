Start with Software Engineering for constrained domain design.
Add a specialty when the task needs its contracts or platform tools.
For technical prose alone, select Repository Knowledge.

| Task | Selection |
| --- | --- |
| Domain values and pure predicates | [Software Engineering](/plugins/software-engineering) |
| General implementation, debugging, review, Git, or CI | Repository instructions and native Git, compiler, and CI tools |
| Kotlin or Gradle | Software Engineering and [Kotlin Engineering](/plugins/kotlin-engineering) |
| Kotlin IntelliJ plugin | Software Engineering, Kotlin Engineering, and [IntelliJ Plugin Development](/plugins/intellij-plugin-development) |
| CLI, JSON Schema, OpenAPI, Pkl, or agent resources | Software Engineering and [Developer Tooling](/plugins/developer-tooling) |
| Documentation, terminology, or repository knowledge | [Repository Knowledge](/plugins/repository-knowledge) |
| Personal configuration | Developer Tooling |

## Describe the task

State the result, the files or system, and the permitted effects.
An installed plugin supplies capabilities.
It does not authorize publication or a personal configuration change.

For a Kotlin review, use a request such as:

```text
Review this Kotlin diff for lost invariants and invalid states.
Use the current callers and contracts as evidence.
Report actionable findings with file locations.
Do not change files.
```

For documentation, use a request such as:

```text
Use controlled-technical-writing and technical-documentation.
Write an installation guide from the current source.
Keep the command syntax and error names exact.
Assess the changed prose with the local Vale procedure.
```

These prompts describe example tasks.
They do not claim a measured model outcome.

## Keep the selection focused

The agent reads a skill when the task needs that procedure.
Installation does not mean that every skill runs.
Repository Knowledge remains optional for routine Kotlin work.

Developer Tooling supplies Python Tooling and tool authoring.
General local delivery procedures remain standalone source references.
The [catalog](https://github.com/amichne/slopsentral/blob/main/source/CATALOG.md) owns the complete list.
The [profile reference](/reference/profiles) describes saved selections.
