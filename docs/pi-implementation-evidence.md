## Contract and owners

The consumer is a Pi session with independently selected capabilities and explicit hook policies.
The protected facts are review obligations, instruction propagation, native tool evidence, configuration identity, and blocking failures.
Release publication, automatic MCP connections, model compliance, filesystem watchers, and shell-effect inference remain outside this change.

| Owner | Contract |
| --- | --- |
| `source/hooks/pi/settings.ts` | Parse settings and policies once, then resolve layers, dependencies, origins, and effective states. |
| `source/hooks/pi/control.ts` | Own saved settings, branch restoration, mutation obligations, resource availability, and result acceptance. |
| `source/hooks/pi/journal.ts` | Collect possible mutation paths and coverage gaps without a subprocess or repository scan. |
| `source/hooks/pi/coordinator.ts` | Admit, serialize, cancel, and reject stale jobs. |
| `source/hooks/pi/runtime.ts` | Interpret hook protocols and preserve finite process failures. |
| `source/hooks/pi/slopsentral.ts` | Adapt native events, commands, prompt context, and completion gates. |
| `source/hooks/pi/menu.ts` | Use native components, themes, keys, and focus under the shared configuration owner. |
| `source/hooks/agents-md-scope.py` | Reuse canonical scope rules with explicit paths and no Git or persistent effects. |
| `tools/projection/Pi.pkl` | Compose canonical profiles, dependencies, capabilities, runtime files, and schemas. |
| `tools/package_pi.py` | Admit the complete projected payload before archive creation. |

Mutation collection precedes the effect and accepts possible changes from failed tools.
Settlement admits one assessment for the pending revision.
An accepted assessment advances `assessedRevision` and preserves pending paths.
An explicit review note resolves the obligation.
Disabled assessment, cancellation, process failure, and stale results never resolve that obligation.

A settings change replaces one layer after admission and atomic persistence.
Malformed first-load settings reject workflow effects until a command repairs the layer.
The menu and repair commands remain usable.
Invalid input preserves the accepted configuration.
Unavailable dependencies reject their affected hooks while other capabilities remain usable.
An invalid capability catalog preserves profile instructions and commands but rejects hooks with unknown dependency facts.
Recovery retries resource availability through the same owner.

Jobs move from admitted to active, then completed, rejected, cancelled, or stale.
Cancellation reports a request without a false completion claim.
Configuration, session, branch, and journal identities govern delivery.
Foreground blocking policies reject background execution at ingress.
Output filters act after protocol interpretation and preserve the decoded result.
