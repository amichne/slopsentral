# Knowledge Backend Handoff

Inspect repository instructions, existing knowledge configuration, source citations, and the requested destination before writing pages.
This skill owns OKF documents and the local checker.
For another backend, preserve its files and identify its format and owner.
If this repository cannot operate that backend, report the missing capability before a write.
Do not select an outside skill, install another tool, or create a second knowledge store.
Do not apply the OKF checker to another backend's pages as a substitute for its own contracts.

For a sibling Git repository, use the local OKF overlay described in knowledge-overlay.md.
A retrieval link does not prove that generation can write into separate storage.
An ordinary code task does not need knowledge generation merely because a backend marker exists.

For an authorized migration, inventory source pages and citations.
Preserve prose and source identity, and account for every page in the destination's existing checks.
Report unresolved formats or unavailable tools before claiming a successful migration.
Counts alone do not prove semantic preservation.
Keep installation and publication within the user's authorized scope.
